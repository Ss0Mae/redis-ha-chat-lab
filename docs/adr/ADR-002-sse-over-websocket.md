# ADR-002 실시간 갱신은 SSE 로 한다

**상태**: 채택 (2026-09-05)

**문제**: 대시보드가 토폴로지(200 ms 스냅샷), 1초 집계, Sentinel/Cluster/Lettuce 이벤트, 장애 주입 결과를 지연 없이 받아야 한다.

**대안**
1. 폴링 — 1초 폴링은 승격 순간(수백 ms)을 놓치고, 200 ms 폴링은 요청이 초당 5건씩 늘어난다.
2. WebSocket — 양방향, 바이너리 가능. Spring 에서 STOMP/브로커 설정이 필요하고, Vite 프록시·재접속 처리를 직접 해야 한다.
3. SSE — 서버→브라우저 단방향 텍스트 스트림. `SseEmitter` 하나로 끝나고 브라우저가 스스로 재접속한다.

**선택**: SSE. 흐름이 단방향(명령은 REST POST)이고 이벤트가 초당 수 개~수십 개라 텍스트로 충분하다.

**단점·한계**: HTTP/1.1 에서 브라우저당 SSE 연결 6개 제한(탭 1개만 씀), 바이너리 불가, 서버가 클라이언트별 emitter 를 들고 있어야 함(수십 명 규모까지만 가정).

**검증**: `GET /api/redis/events/stream` 을 열고 `KILL_PRIMARY` 를 주입하면 `+sdown`→`+odown`→`+switch-master` 가 Sentinel 로그와 같은 순서·같은 초에 도착하는 것을 실험 이벤트 로그와 대조했다.
